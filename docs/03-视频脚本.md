# 演示视频脚本 · 6 分钟版（1080p）

> 目标：5–8 分钟；其中 **2:10–4:20 连续 2 分 10 秒真实 AI 协同录屏**，不剪成“结果展示”。
> 现状：AI 生成/修复已可用；AI 历史与「直接讲解」计划 11/15 落地，4:20 的历史段录制前若未完成，改为「JSON 抽屉 + 重新生成」。
> 录制前先读 [交付台账](./02-交付台账.md) 的“录制前检查”。

## 0. 录制前检查

- 1920×1080，30fps，浏览器 100%，隐藏书签栏 / 系统通知。
- `npm run dev`，`/api/llm/health` 返回 `keyConfigured: true`。
- 清空 localStorage，固定一个已验证主题：**红黑树插入**（会触发一次修复，叙事完整）。
- 预跑一遍：确认 3 轮内能上屏；若第一次就成功，改用「插入排序」并在第二轮故意问“数组扩到 8 个元素”触发质量线修复。
- 录两遍：第一遍完整流程；第二遍补 Prompt/报错特写。最终只交第一遍的连续 AI 段。

## 2. AI 协同段（2:10–4:20，必须连续）

| 时间 | 画面 | 旁白 / 动作 |
|---|---|---|
| 2:10–2:25 | 左页输入「红黑树插入」，点提交 | “不用内置场景，直接说一个长尾主题：红黑树插入。” |
| 2:25–3:00 | 页眉 `AI 正在生成`；左页 trace 字数增长；偶尔停顿 | “流式返回，能看到它正在写 JSON；不是转圈等一个黑盒结果。” |
| 3:00–3:20 | 页眉变 `修复第 1/3 轮`；trace 重新计数 | “第一次没过校验：旋转改了父节点，旧校验器把合法旋转判成拓扑变化。” |
| 3:20–3:50 | 展示错误行 `steps[...] 父节点在第 N 步被改动了`；打开 JSON 抽屉定位 | “这不是模型胡说，是 Schema 和业务规则的边界；我们把‘树允许旋转/新增节点，但旧节点不能消失、根唯一、无环’写进校验。” |
| 3:50–4:20 | 修复完成，右页 12 帧上屏；来源徽标「AI 修复后」；播放两步 | “修复后上屏，来源明确标注 AI 修复后；每一步仍然可以单步、回看、核对 JSON。” |

> 如果现场第一次就通过：把 3:00–3:50 改成“校验通过 → 质量线检查（排序至少 8 元素/24 帧）→ 追问扩到 8 个元素 → 触发一轮修复”，保持真实操作，不要伪造报错。

## 3. 旁白原则

- 不背“技术名词串”，每段只讲一个因果：**为什么要 DSL → 为什么模型不画坐标 → 为什么失败能修**。
- AI 段不要加速、不要剪掉等待；等待时讲“当前在等什么、校验器在查什么”。
- 不要承诺未实现功能：导出、分享、完整多轮聊天都不提；历史段按 11/15 实际落地情况录。
- 结尾不喊口号，回到可复现：仓库、README、Prompt 链、测试命令。
