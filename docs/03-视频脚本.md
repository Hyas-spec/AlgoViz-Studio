# 演示视频脚本 · 6 分钟版（1080p）

> 目标：5–8 分钟；其中 **2:10–4:20 连续 2 分 10 秒真实 AI 协同录屏**，不剪成“结果展示”。
> **逐字台词与配音执行版见 [05-配音台词.md](./05-配音台词.md)**；本文只保留分镜与录制原则。
> 现状：AI 生成/修复、AI 历史与「直接讲解」均已可用；4:20 的历史段可直接录制。
> 录制前先读 [交付台账](./02-交付台账.md) 的“录制前检查”。

## 0. 录制前检查

- **不要用 Xbox Game Bar**：实测输出 1920×1020、约 10fps 的 VFR；用 OBS，画布 1920×1080、30fps 恒定。
- 1920×1080，30fps，浏览器 100%，F11 全屏，隐藏书签栏 / 标签页 / 系统通知。
- `npm run dev`，`/api/llm/health` 返回 `keyConfigured: true`。
- **「方式」必须选中「生成图解」**：占位文字是“追问一句…”，提交后页眉必须是 `AI 正在生成`；如果看到 `AI 正在讲解`，说明选成了“直接讲解”，立即停止重录。
- **Prompt 先复制到剪贴板，录制时 Ctrl+V 粘贴**：不要用中文输入法逐字打，避免留下 `yi'pai'li` 之类的拼音残字；粘贴后停 3–5 秒再提交。
- 清空 localStorage，固定主题：**插入排序（8 个元素）**；实测约 85 秒生成、46 帧、一次通过。
- 预跑一遍：确认 2 分钟内能上屏；如果这次触发修复，按修复分支录；**不要为了制造失败再追加追问**。
- 正式只录一条完整 AI 段；输入 Prompt 后停 3–5 秒，给 Prompt 特写；后期再压 Prompt 字幕，保证作品和 Prompt 同屏。

## 2. AI 协同段（2:10–4:33，必须连续）

| 时间 | 画面 | 旁白 / 动作 |

| 2:10–2:30 | 左页输入 8 元素插入排序 Prompt；停 3–5 秒让 Prompt 入镜；点提交 | “先写一段 Prompt：用 8 个元素演示插入排序，每一步标出已排序区间、当前元素和插入位置。” |
| 2:30–结果上屏 | 页眉 `AI 正在生成`；左页 trace 字数增长；输入框里 Prompt 还在；生成约 30–85 秒 | “Prompt 还在输入框里，页眉已经变成 AI 正在生成；左边是流式 JSON，右边是当前工作区。” |
| 结果上屏–4:20 | 来源 `AI 生成`；四十多帧；后期压入 Prompt 字幕条；播放/JSON 补足时长 | “这次一次通过；8 个元素、四十多帧，质量线要求排序至少 8 个元素、24 帧。” |

> **评审要同时看到作品和 Prompt**：提交成功后输入框会清空，Prompt 不会自己留在画面里。必须在后期加一条“本次 Prompt”字幕或画中画；不要用 AI 历史里的标题代替完整 Prompt。

> 如果这次触发修复：页眉只会显示「修复第 N/3 轮」，不显示完整报错文本；用旁白说明“质量线/校验没过，进入修复”，来源会变成「AI 修复后」。不要为了制造失败再追加追问。

## 3. 旁白原则

- 不背“技术名词串”，每段只讲一个因果：**为什么要 DSL → 为什么模型不画坐标 → 为什么 Prompt 能被约束**。
- AI 段不要加速、不要剪掉等待；等待时讲“当前在等什么、校验器在查什么”。
- 不要承诺未实现功能：导出、分享、完整多轮聊天都不提；历史与问答已落地，按实际录。
- 结尾不喊口号，回到可复现：仓库、README、Prompt 链、测试命令。
