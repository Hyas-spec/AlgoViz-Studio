## 1. 选题与痛点

- 目标用户：计算机/理工科学生、助教、课堂演示者。
- 痛点：算法过程不可见；静态图不能单步；通用聊天给代码但不给可核对的动画；题库式网站只覆盖常见题。
- 现有方案对比：题库可视化 / 通用 Chat / 手工画图 / 本项目。
- 一句定位：自然语言 → 受约束的 Scene DSL → 确定性动画。

## 2. 方案与创新

- 双轨：内置引擎（确定性、零延迟）+ AI 生成（长尾）。
- 关键取舍：模型不生成坐标，只给拓扑/顺序；渲染器负责布局。
- 闭环：生成 → 校验 → 修复 → 上屏 → 单步/回看/JSON 核对（历史为 11/15 计划）。
- 与“套壳聊天”的区别：结构化 Schema + 业务规则 + 质量线 + 修复轮。

## 3. 系统架构

- 前端：React 19 + TS strict + Vite 8；状态用 `useState/useMemo`，不引 Zustand。
- 图版：Canvas 2D；array/tree/graph/sequence 四个渲染器。
- 服务端：Vite middleware `/api/llm`，Key 只在 `.env.local`，支持 SSE。
- 数据流图：输入 → routeScene 规则路由 → 未命中 → `generateScene` → SSE → parse → validate → repair → Scene → Figure。
- 目录：`src/lib/ai/{prompt,client,generate}.ts`、`src/lib/dsl.ts`、`src/lib/engines/`。

## 4. Scene DSL

- `Scene` / `Step` / 四态 `state` 字段表。
- Zod 约束：步数、长度、枚举、必填。
- 业务校验：数组下标/区间；树根唯一、父节点存在、无环、side 不重复；**允许旋转/新增节点，旧节点不消失**；图端点/自环；时序泳道/消息引用。
- 质量线：排序 ≥24 帧且 8 元素；树/图 ≥12；查找 ≥8；时序 ≥5；最后一帧 `doneAll`；`codeLine` 范围。
- 示例：选择排序 8 帧 few-shot；红黑树 12 帧实际输出。

## 5. Prompt 工程与意图控制

- System：角色、字段表、硬规则、质量线、8 帧 few-shot、只输出 JSON。
- User：原始问题 ≤200 字。
- 解析：剥 ```json 围栏 → 首尾大括号 → JSON.parse。
- 修复：`{path,message}[]` 回喂原输出，≤3 轮；树/图/时序的结构检查提示。
- 三条已完成 Prompt 链：00 界面选型 / 01 脚手架 / 02 DSL 与排序；03 AI 修复链可选（需截图）。
- 真实案例：红黑树第一次报“父节点在第 N 步被改动” → 定位静态树约束 → 放宽为旋转/新增节点 → 12 帧上屏。

## 6. 生成质量保障

- 三层：JSON 可解析 → Zod 结构 → 业务/质量线。
- 失败降级：保留当前场景、提示具体 path、trace 保留原始输出；不写历史/URL。
- 修复成本：最多 3 轮；每轮重新流式生成，失败不污染当前场景。
- 测试：87 例（引擎、校验、AI 解析/修复/质量线、树旋转）。
- 未做：缓存、生成限流、多模型 fallback（列为展望）。

## 7. 可复现性论证

- 内置引擎：纯函数 + 固定输入 → 固定 steps；同参数同帧。
- AI：JSON 快照可存/可 diff；同 Prompt 不保证逐字相同，但结构可校验；当前场景刷新即丢（历史 11/15 接入）。
- URL：`?scene=&step=&size=&pivot=&levels=&start=&loss=` 可复现内置场景。
- 干净目录：`npm ci && npm run dev`；11/16 实测（待做）。
- 构建：662.99KB raw / 203.94KB gzip；在 350KB gzip 预算内，但有单 chunk 警告。
