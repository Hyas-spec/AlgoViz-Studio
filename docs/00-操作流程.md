## 4. Git 与 GitHub 实时同步规范

### 4.1 提交节奏
- 每完成一个可演示的小功能 → 提交一次；每修一个 bug → 提交一次。
- 一天 3–6 次，提交信息写清楚「做了什么」，不要 `update`、`fix`。
- 推送失败不阻塞开发：先本地 commit，恢复后一次 push。

### 4.2 提交信息格式
```
feat(spread): two-page layout with spine and page numbers
feat(figure): array plate on 28px grid
feat(engine): add quicksort step generator
fix(llm): retry once on JSON parse failure
docs(prompts): archive iteration 02
test(engine): cover merge sort terminal state
style(spread): tighten page margins
chore: add gif worker to public
```

### 4.3 绝对不能提交
- `.env.local`、任何 API Key；
- `node_modules/`、`.npm-cache/`、`dist/`；
- 录屏原片（体积大，放网盘，仓库只放脚本和截图）。

### 4.4 仓库结构（评审友好）
```
README.md            ← 10 分钟复现 + 双页截图 + 架构图
docs/
  design/            ← 双页版式基线（concept-spread.png / .html）
  prompts/           ← 4 条完整 Prompt 链（核心得分材料）
  tech-doc/          ← 技术文档源文件
  video/             ← 分镜脚本
src/ ...
```

## 5. Prompt 留痕（25% 的命门）

评审要看的不是「你用了 AI」，而是「你怎么指挥 AI、怎么修」。每轮迭代固定记录：

```md
# 迭代 02 · AI 生成与校验修复
- 日期：2026-11-15
- 工具/模型：DeepSeek-Chat / Cursor
- 目标：让自然语言生成可播放的 DSL
- Prompt（原文，完整贴出）：
- AI 输出摘要：
- 我发现的问题：
- 修复指令（原文）：
- 最终结果：
- 对应 commit：a1b2c3d
- 截图：./assets/02-01.png
```

**必须凑齐的 4 条链（评审要求至少 3 条）：**
0. 界面选型：4 个方向（Stage / Spread / Poster / Terminal）→ 选定讲义双页，记录取舍；
1. 脚手架 + DSL 设计（从需求到 Schema）；
2. AI 生成失败 → 校验报错 → 修复 → 通过（最能体现「意图控制」）；
3. 导出/性能问题定位与优化（体现工程能力）。

**截图清单（每轮 3–5 张）：** 4 个方向的对比图、输入 Prompt 的界面、生成中的状态、报错/校验信息、修复后的结果、对应代码 diff。

## 6. 演示视频（5–8 分钟，必须含 ≥2 分钟 AI 协同）

### 6.1 分镜（目标 5:30）

| 时间 | 画面 | 旁白要点 |
|---|---|---|
| 0:00–0:30 | 标题 + 痛点：文字讲算法，学生脑补 | 「一句话，能不能直接看到过程？」 |
| 0:30–1:20 | 双页封面 → 左页输入「快速排序」→ 右页图版落墨 | 左页讲义 + 右页图版一屏内闭环，规则路由 0 延迟 |
| 1:20–2:10 | 右页单步、回退、拖标尺；左页参数改动 | 参数联动、复杂度数字变化 |
| 2:10–3:20 | 左页输入「TCP 三次握手，演示一次丢包重传」→ 页眉流式状态 → 校验 → 修复 → 右页播放 | **AI 协同核心段**：展示 Prompt、失败、修复 |
| 3:20–4:00 | 页眉「导出」：GIF + 教学卡片 + 讲稿 | 学习闭环：理解 → 输出 |
| 4:00–4:50 | 双页版式图 + DSL 片段 + Prompt 策略 | 为什么不是「套壳」：Schema、双轨、可复现 |
| 4:50–5:30 | 10 分钟复现（终端 `npm ci && npm run dev`）+ 仓库 | 评委可一键复现 |

> AI 协同段必须**连续录屏 ≥2 分钟**：真实输入、真实等待、真实报错、真实修复，不要剪成「结果展示」。

### 6.2 录制设置
- 1920×1080，30fps，浏览器 100% 缩放，隐藏书签栏；
- 系统通知关闭；提前清空历史/缓存，保证每次演示一致；
- 录两遍：第一遍走流程，第二遍补特写（Prompt 输入、校验报错）。
