# 配音台词与录制执行版（6 分 23 秒）

> 目标：5–8 分钟、1920×1080、**无声录屏 + 后期 AI 配音**。
> 本文是逐字台词，不是分镜摘要；每个时间段都写了画面动作、台词、停顿和异常时的改法。
> 录制前先看 [03-视频脚本.md](./03-视频脚本.md) 的检查项；AI 历史/直接讲解已落地，可直接按本稿录。

## 0. 制作方式

你录**无声画面**，我按本文生成**分段 AI 配音**（Windows 中文语音或 Edge TTS），你在剪映里把音频贴到对应画面。

推荐流程：

1. 按下面的 8 段分别录屏，每段开头停 1 秒、结尾停 1 秒；文件名 `01-封面.mp4` … `08-仓库.mp4`。
2. 我按段生成 `01.wav` … `08.wav`；你导入剪映，对齐每段开头。
3. 如果某段画面比配音短，**延长画面停留**，不要加速 AI 段；如果比配音长，补一句解释或留 1–2 秒静帧。
4. 最后统一加字幕（可用剪映自动识别，再按本稿校对）。

> 视频评审要求“AI 协同 ≥2 分钟连续录屏”；第 5 段必须一镜到底，不能把等待剪掉。

## 1. 分段台词

### 01 · 0:00–0:25 开场

**画面**：首页/双页首屏，鼠标不急着动；开头 3 秒标题卡（后期叠字，不必录）。

**台词**：

> 文字讲算法，学生只能脑补。步骤一多，图就断了。我们想让一句话，直接变成可以单步、可以回看的算法讲义。这就是 AlgoViz，算法视界。

**停顿**：说完停 0.5 秒，再进下一段。

### 02 · 0:25–1:10 双页与基本播放

**画面**：`/?scene=quick`；鼠标从左页正文移到右页；点播放，暂停；点单步；拖标尺到分区中段。

**台词**：

> 画面左边是讲义，右边是图版。以快速排序为例：正文、公式、伪代码和动画在同一屏里对齐。
>
> 点播放，柱子开始移动；点单步，可以停在任意一帧；拖标尺，直接回到分区的那一刻。
>
> 不需要在文档、代码和动画之间来回切。讲课的人可以指着左边讲，学生盯着右边看。

**动作提示**：拖标尺时停 1 秒，让画面跟上“回到分区那一刻”。

### 03 · 1:10–1:50 参数、字号、伪代码跳帧

**画面**：把 n 从 10 改到 8；按 `A+` 到 126%；点伪代码第 3 行；再按 `A−` 回 100%。

**台词**：

> 参数也能直接改。把数组从十个缩到八个，画面立刻重算，复杂度数字跟着变。
>
> 投影时按 A+，正文、公式、代码和图里的节点标签一起放大，后排也能看清。
>
> 点伪代码的任意一行，会跳到对应帧。

**动作提示**：点伪代码后停 1 秒，等画面切到对应帧再继续说。

### 04 · 1:50–2:10 内置场景与规则路由

**画面**：切到“握手”，打开丢包；再回首页（或快速排序），为下一段 AI 生成留出干净起点。

**台词**：

> 常用场景不请求模型：排序、树、图、TCP 握手，十个内置场景，打开就能讲。规则路由让它们零延迟。

**动作提示**：这段只做转场，不展开讲 TCP。

### 05 · 2:10–4:33 AI 协同核心段（一镜到底）

**画面**：回到快速排序/干净双页；在左页底部输入：

`用 8 个元素演示插入排序，每一步标出已排序区间、当前元素和插入位置`

先停 3–5 秒让 Prompt 入镜，再提交；不切镜头。页眉出现“AI 正在生成”，左页 trace 字数增长；成功后右页四十多帧上屏、来源“AI 生成”。结果上屏后，在画面底部压一条“本次 Prompt”字幕，让 Prompt 和作品同屏；播放两步、展开 JSON。

**关键**：提交成功后输入框会清空，Prompt 不会自己留在画面里；必须在后期加一条 Prompt 字幕或画中画，才能满足“作品 + Prompt 同时可见”。不要用 AI 历史里的标题代替完整 Prompt。可直接叠 [prompt-insertion-strip.png](../mockups/prompt-insertion-strip.png)（1920×150 透明字幕条）。

**台词**：

> 接下来换一个更直观的核心模块：插入排序。先写一段 Prompt：用 8 个元素演示插入排序，每一步标出已排序区间、当前元素和插入位置。
>
> 注意，Prompt 还在输入框里，页眉已经变成 AI 正在生成。左边不是转圈，而是流式返回的 JSON，字数实时在涨；右边是当前工作区。
>
> 这次一次通过。校验器逐项检查：8 个元素、四十多帧，每一步的 codeLine 和 doneAll 都合法；质量线要求排序至少 8 个元素、24 帧，这一版都过了。
>
> 结果上屏。来源是 AI 生成，四十多帧。我们把刚才这条 Prompt 压在画面里，左边 Prompt、右边作品，同一屏能对照：Prompt 写清楚了“8 个元素、已排序区间、当前元素、插入位置”，图版就按这个讲。
>
> 可以单步、可以拖标尺，也可以展开 JSON，核对它到底生成了什么。这就是意图控制：不是让模型随便画，而是把“讲什么、讲多细”写进 Prompt，再用 DSL 和校验器约束它。

**等待时怎么说**：

- 如果生成很慢：说“现在它在流式生成，Prompt 和字数都还在画面上”，然后**闭嘴等**，不要用“快好了”填满。
- 如果触发修复：页眉会变“修复第 N/3 轮”，把“这次一次通过”改成“第一次被质量线挡了，进入修复”；来源会变成“AI 修复后”。不要说“没有失败”。
- 如果三次仍失败：保留失败提示，整段重录；不要剪一个成功结果接上。可换回红黑树或另一个已验证主题。
- 如果实际帧数不是 46：按画面上的实际数字说，四十多帧即可，不要背死。

**时长控制**：这段画面必须 ≥2:00；Prompt 停留 3–5 秒。生成快时（30–60 秒），结果段拉到 60–90 秒（播放/单步/JSON）；生成慢时（85 秒以上），结果段 30 秒即可。两种都补到 2:10。

### 06A · 4:33–4:48 直接讲解

**画面**：左页切「直接讲解」，输入「为什么快速排序最坏是 O(n²)？」；右页出现问答卡：结论、5 条要点、公式、代码、追问。

**台词**：

> 除了画图，也可以直接问概念。切到“直接讲解”，它返回的不是动画，而是一张结构化问答卡：先给结论，再给 3 到 5 条要点、公式和代码，最后给可继续追问的问题。

### 06B · 4:48–5:03 AI 历史与 JSON

**画面**：打开 AI 历史，点刚才的“插入排序”；恢复后输入框会自动回填 Prompt，正好和右侧 46 帧作品同屏；停 3 秒，再展开 JSON 抽屉，滚动到 `layout` / `steps` 停 2 秒。

**台词**：

> 生成和讲解都会进 AI 历史。刚才的插入排序还在，点一下就能恢复，刷新也不丢；右边这份 JSON 就是它的完整结构。

### 07 · 5:03–5:48 架构与可复现性

**画面**：切到一张架构图 / DSL 片段 / system prompt 节选（可用 PPT 或静态页面）；鼠标指 `Scene DSL`、`validate`、`repair` 三个框。

**台词**：

> 为什么不是套壳？因为模型不碰坐标。它只输出 Scene DSL：数组、树、图、时序四种状态；Zod 管结构，业务规则管引用和几何；布局由渲染器确定性计算。
>
> 同一份 JSON，在 1440、1024、手机上都长一样。模型负责“讲什么”，渲染器负责“怎么画”，中间那层校验负责“不能乱画”。

### 08 · 5:48–6:23 仓库与复现

**画面**：终端 `npm ci` 完成、`npm run dev` 起服务；浏览器打开首页；GitHub 仓库页 `docs/prompts/` 目录。

**台词**：

> 代码在 GitHub，README 里有十分钟复现；六十七次细粒度提交，三条完整 Prompt 链，连同对话截图都在 docs/prompts。
>
> 十个内置场景，九十二个测试。你可以现在 clone 下来，跑 npm ci 和 npm run dev。

**收尾**：画面停在仓库 README，音乐/配音收，不再加口号。

## 3. 配音方案

### 我能做的

- 按本文生成 **中文 AI 配音**（Windows `Microsoft Huihui` 或 Edge TTS `zh-CN-XiaoxiaoNeural` / `YunxiNeural`）。
- 先出 20–30 秒试听，你确认音色/语速后再生成全片。试听（Windows Huihui，17 秒）：[voice-sample.wav](assets/voice-sample.wav)
- 按段输出 `01.wav` … `08.wav`，你在剪映里对齐。

### 推荐软件（你自己做或替换音色）

| 工具 | 用途 | 备注 |
|---|---|---|
| 剪映专业版 | 文本朗读 + 自动字幕 + 对齐 | 免费、中文自然，最省事 |
| Edge 浏览器“朗读” / Edge TTS | 免费神经语音 | `zh-CN-XiaoxiaoNeural` 女声、`YunxiNeural` 男声 |
| 讯飞智作 / 魔音工坊 | 中文 TTS、多音色 | 有免费额度，适合正式旁白 |
| ElevenLabs | 更自然的多语言 TTS | 付费；中文可用但成本高 |
| Adobe Podcast Enhance | 真人录音降噪 | 不是 TTS；你以后有麦克风可用 |

### 重要提醒

- 合成音不是真人声；如果比赛规则要求“作者本人讲解”，AI 配音可能不合规，录制前确认规则。
- 若允许 AI 配音，建议在视频简介/片尾标注“AI 合成配音”，避免争议。
- 不要用带版权争议的背景音乐；无声或轻音乐即可，音量压到 -24dB 以下。

## 4. 录屏前检查

- [ ] **不要用 Xbox Game Bar**：实测会输出 1920×1020、约 10fps 的 VFR；用 OBS，画布 1920×1080、30fps 恒定。
- [ ] 1920×1080、30fps、浏览器 100%、F11 全屏、隐藏书签栏与标签页
- [ ] **「方式」必须选中「生成图解」**：占位文字应是“追问一句…”，提交后页眉必须是“AI 正在生成”；看到“AI 正在讲解”立刻停，重录
- [ ] Prompt 先复制到剪贴板，录制时 `Ctrl+V` 粘贴；不要用中文输入法逐字打，避免拼音残字
- [ ] 提交后的结果段至少 60 秒：播放/单步/JSON 都要拍到；生成快时用结果段补足 2:00
- [ ] 清空 localStorage，固定“插入排序（8 元素）”能在 2 分钟内上屏；若触发修复，按修复分支录
- [ ] `/api/llm/health` 为 `keyConfigured: true`
- [ ] 第 05 段一镜到底，≥2:00，不剪等待
- [ ] 不出现 `.env.local`、API Key、个人信息
- [ ] 片尾有仓库地址与 `npm ci && npm run dev`
- [ ] 最终 MP4 时长 5–8 分钟，音画对齐
