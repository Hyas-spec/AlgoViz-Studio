# 配音台词与录制执行版（6 分 10 秒）

> 目标：5–8 分钟、1920×1080、**无声录屏 + 后期 AI 配音**。
> 本文是逐字台词，不是分镜摘要；每个时间段都写了画面动作、台词、停顿和异常时的改法。
> 录制前先看 [03-视频脚本.md](./03-视频脚本.md) 的检查项；AI 历史/直接讲解 11/15 落地后，再按本稿录。

## 0. 制作方式

你录**无声画面**，我按本文生成**分段 AI 配音**（Windows 中文语音或 Edge TTS），你在剪映里把音频贴到对应画面。

推荐流程：

1. 按下面的 7 段分别录屏，每段开头停 1 秒、结尾停 1 秒；文件名 `01-封面.mp4` … `07-仓库.mp4`。
2. 我按段生成 `01.wav` … `07.wav`；你导入剪映，对齐每段开头。
3. 如果某段画面比配音短，**延长画面停留**，不要加速 AI 段；如果比配音长，补一句解释或留 1–2 秒静帧。
4. 最后统一加字幕（可用剪映自动识别，再按本稿校对）。

> 视频评审要求“AI 协同 ≥2 分钟连续录屏”；第 4 段必须一镜到底，不能把等待剪掉。

## 1. 分段台词

### 01 · 0:00–0:25 开场

**画面**：标题页 / 双页首屏，鼠标不急着动。

**台词**：

> 文字讲算法，学生只能脑补。步骤一多，图就断了。我们想让一句话，直接变成可以单步、可以回看的算法讲义。这就是 AlgoViz，算法视界。

**停顿**：说完停 0.5 秒，再进下一段。

### 02 · 0:25–1:10 双页与基本播放

**画面**：`/?scene=quick`；鼠标从左页正文移到右页；点播放，暂停；点单步；拖标尺到分区中段。

**台词**：

> 画面左边是讲义，右边是图版。以快速排序为例：正文、公式、伪代码和动画在同一屏里对齐。
>
> 点播放，柱子开始移动；点单步，可以停在任意一帧；拖标尺，直接回到分区的那一刻。
>
> 不需要在文档、代码和动画之间来回切。讲课的人可以指着左边讲，学生盯着右边看。

**动作提示**：拖标尺时停 1 秒，让画面跟上“回到分区那一刻”。

### 03 · 1:10–1:50 参数、字号、伪代码跳帧

**画面**：把 n 从 10 改到 8；按 `A+` 到 126%；点伪代码第 3 行；再按 `A−` 回 100%。

**台词**：

> 参数也能直接改。把数组从十个缩到八个，画面立刻重算，复杂度数字跟着变。
>
> 投影时按 A+，正文、公式、代码和图里的节点标签一起放大，后排也能看清。
>
> 点伪代码的任意一行，会跳到对应帧。

**动作提示**：点伪代码后停 1 秒，等画面切到对应帧再继续说。

### 04 · 1:50–2:10 内置场景与规则路由

**画面**：切到“握手”，打开丢包；再切回快排。

**台词**：

> 常用场景不请求模型：排序、树、图、TCP 握手，十个内置场景，打开就能讲。规则路由让它们零延迟。

**动作提示**：这段只做转场，不展开讲 TCP。

### 05 · 2:10–4:20 AI 协同核心段（一镜到底）

**画面**：回到首页；在左页输入 `红黑树插入`；提交；不切镜头。页眉出现“AI 正在生成”，左页 trace 字数增长；出现“修复第 N/3 轮”；右页最终上屏 12 帧，来源“AI 修复后”；播放两步。

**台词**：

> 接下来是最关键的一段：不用题库，直接说一个长尾主题——红黑树插入。
>
> 注意看页眉：AI 正在生成。左边不是转圈，而是流式返回的 JSON，已经收到多少字，实时在涨。
>
> 第一次生成没有直接通过。校验器报了一个很具体的错误：第五步，节点 n10 的父节点被改动了。
>
> 这不是模型胡说。红黑树插入本来就要旋转，旋转一定会改父子关系；旧校验器却要求整棵树不能动。也就是说，失败的原因在规则边界，不在模型。
>
> 我们改了两件事：允许树旋转、允许新增节点，但旧节点不能消失，每一帧仍然根唯一、不能有环；同时把修复轮上限提到三轮。
>
> 现在它进入修复，重新生成。注意，这不是把错误藏起来，错误路径、原始 JSON 都留在 trace 里。
>
> 修复完成，右页上屏。来源标记是 AI 修复后。十二帧，可以单步，可以拖标尺，也可以展开 JSON，核对它到底生成了什么。
>
> 这就是我们说的意图控制：不是让模型画一张好看的图，而是让它交出一份受约束、可校验、可修复的结构。

**等待时怎么说**：

- 如果生成很慢：重复最后一句“现在它进入修复，重新生成”，然后**闭嘴等**，不要用“快好了”填满。
- 如果第一次就成功：把“第一次没有直接通过”改成“这次一次通过，但校验器仍然逐项检查”；随后打开 JSON 指 `layout`、`steps`，再补一句“如果它改了树的结构，业务规则会要求修复”。
- 如果三次修复仍失败：不要剪掉，直接说“这次没有收敛，我们保留当前场景和原始输出；这是下一步要改的边界”，然后切到已经验证成功的 `Prim` 或 `插入排序`。**不要伪造成功**。

**时长控制**：这段画面必须 ≥2:00；台词本身约 1:30，留 30 秒真实等待/操作，正好 2:10。

### 06 · 4:20–4:50 AI 历史与 JSON

**画面**：打开 AI 历史，点刚才的红黑树；恢复后展开 JSON 抽屉，滚动到 `layout` / `steps` 停 2 秒。

**台词**：

> 生成的结果不是一次性截图。打开 AI 历史，刚才的红黑树还在；点一下就能恢复，刷新也不丢。
>
> 每一条都保留原始问题、场景和来源。右边这份 JSON 就是它的全部结构，可以核对，也可以作为下一次生成的输入。

**如果历史功能当天未完成**：改成“生成结果不是一次性截图；右侧 JSON 抽屉保留完整结构”，不要提“历史/刷新不丢”。

### 07 · 4:50–5:35 架构与可复现性

**画面**：切到一张架构图 / DSL 片段 / system prompt 节选（可用 PPT 或静态页面）；鼠标指 `Scene DSL`、`validate`、`repair` 三个框。

**台词**：

> 为什么不是套壳？因为模型不碰坐标。它只输出 Scene DSL：数组、树、图、时序四种状态；Zod 管结构，业务规则管引用和几何；布局由渲染器确定性计算。
>
> 同一份 JSON，在 1440、1920、手机上都长一样。模型负责“讲什么”，渲染器负责“怎么画”，中间那层校验负责“不能乱画”。

### 08 · 5:35–6:10 仓库与复现

**画面**：终端 `npm ci` 完成、`npm run dev` 起服务；浏览器打开首页；GitHub 仓库页 `docs/prompts/` 目录。

**台词**：

> 代码在 GitHub，README 里有十分钟复现；五十多次细粒度提交，三条完整 Prompt 链，连同对话截图都在 docs/prompts。
>
> 十个内置场景，八十七个测试。你可以现在 clone 下来，跑 npm ci 和 npm run dev。

**收尾**：画面停在仓库 README，音乐/配音收，不再加口号。

## 3. 配音方案

### 我能做的

- 按本文生成 **中文 AI 配音**（Windows `Microsoft Huihui` 或 Edge TTS `zh-CN-XiaoxiaoNeural` / `YunxiNeural`）。
- 按段输出 `01.wav` … `08.wav`，你在剪映里对齐。
- 先出 20–30 秒试听，你确认音色/语速后再生成全片。

### 推荐软件（你自己做或替换音色）

| 工具 | 用途 | 备注 |
|---|---|---|
| 剪映专业版 | 文本朗读 + 自动字幕 + 对齐 | 免费、中文自然，最省事 |
| Edge 浏览器“朗读” / Edge TTS | 免费神经语音 | `zh-CN-XiaoxiaoNeural` 女声、`YunxiNeural` 男声 |
| 讯飞智作 / 魔音工坊 | 中文 TTS、多音色 | 有免费额度，适合正式旁白 |
| ElevenLabs | 更自然的多语言 TTS | 付费；中文可用但成本高 |
| Adobe Podcast Enhance | 真人录音降噪 | 不是 TTS；你以后有麦克风可用 |

### 重要提醒

- 合成音不是真人声；如果比赛规则要求“作者本人讲解”，AI 配音可能不合规，录制前确认规则。
- 若允许 AI 配音，建议在视频简介/片尾标注“AI 合成配音”，避免争议。
- 不要用带版权争议的背景音乐；无声或轻音乐即可，音量压到 -24dB 以下。
