## 1. 选题与痛点

### 1.1 谁的问题

算法与数据结构课程里，最难的往往不是记住结论，而是理解“过程”：

- 学生看静态图，知道快排要分区，却不知道指针每一步怎么移动；
- 看伪代码能背出 Dijkstra 的松弛，却无法把“待确定集合”和路径变化对应起来；
- TCP 三次握手背得出 SYN / ACK，却说不清为什么两次不够、丢包后谁重传；
- 老师做课堂演示时，要在 PPT、代码、动画网站之间来回切换，学生注意力被切碎。

本项目面向计算机/理工科学生、考研复习者、助教与课堂演示者，把“一句话描述”转换成一份可单步、可回退、可调参的算法讲义。

### 1.2 现有方案的不足

| 方案 | 优点 | 不足 |
|---|---|---|
| 静态教材/PPT | 结构清楚、可打印 | 过程不可见，学生只能脑补 |
| 题库式可视化网站 | 常见算法覆盖好 | 只覆盖固定题目，长尾主题无法生成 |
| 通用聊天机器人 | 能回答概念、能写代码 | 给出的是文字/代码，不是可核对的分步动画 |
| 手工做动画 | 完全可控 | 成本高，课堂场景来不及 |

因此，本项目不把“生成一段动画”做成一次性视频，而是生成一份**结构化、可校验、可复现的 Scene DSL**：模型负责“讲什么”，渲染器负责“怎么画”，中间层负责“不能乱画”。

## 2. 方案与创新

### 2.1 双轨生成

系统有两条生成路径：

1. **内置引擎**：排序、树遍历、BFS / Dijkstra、TCP 握手/挥手等 10 个场景由确定性代码生成，命中关键词直接切换，0 延迟、断网可演示、参数即时重算。
2. **AI 生成**：未命中的长尾主题走 `/api/llm`，流式生成 Scene DSL，再经过结构、业务与质量校验；失败自动修复。

内置引擎保证“常用场景永远能演示”，AI 保证“没见过的主题也有机会生成”。这比纯 AI 或纯题库都更稳。

### 2.2 关键取舍

- **模型不生成坐标**：坐标由 array / tree / graph / sequence 四个确定性渲染器计算，避免节点重叠、越界和分辨率不一致。
- **模型只输出 JSON**：不执行 AI 生成的代码，不 `eval`，攻击面小。
- **先校验再上屏**：Schema、业务规则、质量线三层检查；不合格的 JSON 不进入画布。
- **失败可解释**：错误带 `path + message`，既回喂模型修复，也显示在 trace 中；不静默吞掉。

### 2.3 与“套壳聊天”的区别

普通聊天直接输出文字或代码；本项目的输出必须满足：

- 四类图版之一的字段约束；
- 节点/边/数组/泳道的引用完整性；
- 帧数、终态、代码行范围等教学质量线；
- 可被渲染器稳定绘制、可被 JSON 抽屉核对。

AI 只是“讲义作者”，不是“画布操作者”。

## 3. 系统架构

### 3.1 前端

- React 19 + TypeScript strict + Vite 8；
- 状态用 `useState` / `useMemo`，场景规模小，不引入 Zustand；
- 双页版式：左页讲义，右页图版；CSS 变量控制纸/墨/钴蓝/朱砂；
- 四个 Canvas 2D 渲染器：`figure/array.ts`、`tree.ts`、`graph.ts`、`sequence.ts`；
- KaTeX 渲染公式；`JsonDrawer` 提供只读 DSL 核对；
- AI 历史存 `localStorage`，最多 20 条，`#ai=<id>` 恢复。

### 3.2 服务端

- Vite middleware `/api/llm`，dev 与 preview 共用；
- Key 只在 `.env.local`，不进入浏览器；代理只接受 OpenAI 兼容请求；
- SSE 透传，前端逐块解析 `data:`，支持 `AbortSignal` 停止；
- 静态部署时可替换为 Serverless 适配（P2）。

### 3.3 数据流

```text
输入
  → routeScene 规则路由（命中 → 内置 Scene）
  → 未命中 → generateScene
      → system prompt + user prompt
      → /api/llm SSE
      → extractJson → validateScene → qualityIssues
      → 失败：issues 回喂，最多 3 轮
      → 成功：Scene → Figure / 左页讲义 / JSON 抽屉
  → 历史：localStorage + #ai=<id>
```

直接讲解模式走另一条链：

```text
输入 → 显式选择「直接讲解」
  → generateAnswer → answerSchema → 最多 2 轮修复
  → AnswerCard（右页）+ answerToScene（左页排版）
```

## 4. Scene DSL

### 4.1 Scene 与 Step

`Scene` 是一次完整讲义的元数据与步骤集合；`Step` 是单帧：

```ts
interface Step {
  caption: string;
  codeLine: number;
  metrics?: { label: string; value: string }[];
  doneAll?: boolean;
  state: ArrayState | TreeState | GraphState | SequenceState;
}
```

`Scene` 还包含标题、章节、摘要、正文、公式、复杂度、代码、事实表、大纲、参数、来源等字段。

### 4.2 四态联合

- `array`：values、pivot、compare、swap、locked、range；归并另有 aux（左右段、指针、目标位）。
- `tree`：nodes（id/label/parent/side）、order、current、frontier、frontierLabel。
- `graph`：nodes、edges、visited、frontier、path、current、dist、frontierLabel。
- `sequence`：lanes、messages（from/to/label/tone/lost）、active、notes。

四种状态共用 `Figure` 的调度接口，布局由渲染器计算。

### 4.3 校验与树旋转

Zod 负责结构，`inspectScene()` 负责业务规则：

- 数组下标/区间/交换/锁定合法；
- 树根唯一、父节点存在、无环、side 不重复；**允许旋转改变 parent/side、允许新增节点，但旧节点不能消失**；
- 图边端点存在、无自环；`dist` 引用不重复；
- 时序消息端点属于 lanes，消息 id 不重复。

红黑树插入第一次生成失败，正是因为旧校验器要求“整场父子关系不变”，而旋转必然改变 parent/side。修正后，红黑树 12 帧、修复 1 轮上屏。这说明业务规则本身也需要被真实算法检验，不能只按“静态树”假设写死。

### 4.4 质量线

结构合法不代表教学内容合格。当前质量线：

- 排序场景：至少 24 帧、8 个元素；
- 树：至少 12 帧；图：至少 10 帧；
- 查找：至少 8 帧；时序：至少 5 帧；
- 最后一帧 `doneAll: true`；
- `codeLine` 在 `1..code.length`；
- 模型偶发把 `outline.step` 写成 `steps.length`，系统先夹到最后一帧（差一格式笔误），不因小错重生成。

## 5. Prompt 工程与意图控制

### 5.1 System Prompt

`src/lib/ai/prompt.ts` 的 system prompt 包含：

- 角色：AlgoViz 的 Scene DSL 生成器，只输出 JSON；
- 四态字段、枚举、数量/长度约束；
- 布局选择规则：排序/查找优先 array，树 tree，图 graph，协议 sequence；
- 质量线：排序 8 元素/24 帧、树 12 帧、图 10 帧、时序 5 帧；
- 一个完整 8 帧选择排序 few-shot（只作字段形状示例，长度不照抄）；
- 修复规则：引用完整性、树旋转、根唯一、无环、时序 lanes。

### 5.2 解析与修复

1. 剥离 ```json 围栏，截取首尾大括号；
2. `JSON.parse`；
3. `validateScene()`：Zod + 业务规则；
4. 失败把 `{path, message}[]` 与原始输出回喂，最多 3 轮；
5. 成功写 `source: 'ai'`，修复成功显示「AI 修复后」；
6. 仍失败保留原始 JSON 在 trace，当前场景不污染。

### 5.3 真实案例：红黑树

用户输入「红黑树插入」，第一次生成报：

```text
steps[5].state.nodes 节点 n10 的父节点在第 5 步被改动了
```

根因不是模型乱写，而是校验器把合法的旋转判成非法。修复两处后成功：

- `dsl.ts`：允许旋转/新增节点，保留旧节点不消失、根唯一、无环、side 合法；
- `generate.ts`：修复轮从 2 提到 3，质量线按 category/layout 计算；
- 结果：12 帧、AI 修复后。

### 5.4 直接讲解

显式选择「直接讲解」时不走 Scene 质量线，而走 `answerSchema`：

- `title / summary / points[3..5] / formula? / code? / followups[2..4]`；
- 右页问答卡，左页复用讲义排版；
- 失败最多 2 轮修复；不冒充动画。

### 5.5 Prompt 链与对话截图

- 00 界面选型：Stage / Spread / Poster / Terminal → 选定双页；
- 01 脚手架与双页：兼容性、fluid 布局修复；
- 02 Scene DSL、三排序、四态、参数/过程量；
- 03 AI 生成/修复 + AI 历史/直接讲解：对话截图在 `docs/prompts/assets/03-01..03-05`。

每轮记录用户原话、AI 建议、失败、修复指令、结果和 commit，避免只展示“成功截图”。

## 6. 生成质量保障

- **三层校验**：JSON 可解析 → Zod → 业务/质量线；
- **修复策略**：结构化 issues 回喂，最多 3 轮；每轮重新流式生成；
- **差一修复**：`outline.step` 夹取，不因格式笔误浪费一轮；
- **降级**：失败保留当前场景，提示具体 path，trace 保留原始输出；
- **测试**：92 例，覆盖引擎、校验、AI 解析/修复/质量线、AI 答案/历史、树旋转；
- **未做**：生成缓存、限流、多模型 fallback（P2）。

## 7. 可复现性论证

- 内置引擎是纯函数：同参数 → 同 Scene；
- 场景是 JSON：可快照、可 diff、可 JSON 抽屉核对；
- URL：`?scene=&step=&size=&pivot=&levels=&start=&loss=` 可复现内置场景；
- AI 历史：localStorage + `#ai=<id>`，刷新不丢；
- 干净目录：2026-11-16 同机 clean worktree 执行 `npm ci`、92 测试、build，dev 5174 无 Key 页面 200；
- AI 的逐字输出不保证相同，但结构可校验；比赛演示固定使用已验证主题。

## 10. 局限与展望

- 只支持四种可视化语法，不适合任意示意图/DP 表；
- AI 场景/讲解存本地，当前不做跨设备分享；
- 无导出（PNG/GIF/Markdown/卡片）与生成缓存；
- 后续：导出、更多图版（DP/链表）、多轮追问、云端同步；
- 结论：先把“可解释、可核对、可复现”做扎实，再扩图版。
